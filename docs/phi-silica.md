# Phi Silica for summaries (T8.3g)

Task T8.3g: could Windows' built-in Phi Silica (`Microsoft.Windows.AI.Text.LanguageModel`, on the Copilot+ NPU) write Earshot's meeting summaries on the Surface instead of llama.cpp on the CPU?

**Verdict: not feasible today.** The model's context window (about 3.5K tokens, shared by instructions, transcript and reply) is smaller than one of our 10-minute chunk prompts; production use needs a Limited Access Feature token from Microsoft plus a signed package identity for the app; and Microsoft removes Phi Silica from retail devices in January 2027 in favour of "Aion Instruct", whose context size and API terms are not yet documented. Revisit when Aion Instruct is documented (early 2027), behind the existing `Generate` trait with llama.cpp kept as the fallback.

How this was established: a documentation review of Microsoft Learn and Windows blogs on 2026-11-03 (sources and page dates below, each claim cited; "UNCONFIRMED" where the docs are silent), plus the read-only Surface check below. No probe was run: calling the API needs a signed identity package registered with Windows and a LAF token (or the experimental SDK channel, which Microsoft says is not for production), which are installs and registrations outside this task's rules (AGENTS ground rule 8) and the owner's decision.

## The Surface (read-only check, 2026-11-03)

- Windows 11 26H1, build 28000.3231 (above the documented minimum, 25H2 build 26200.7309).
- Windows App SDK runtimes already installed by other apps: 1.5 to 1.8, 2.5.1 and 2.6.4 (`Get-AppxPackage`). The runtime install step would not be needed on this machine; package identity and the LAF token still would.
- Whether the Phi Silica model itself is present was not checked (it is a system component, not an app package; Settings > System > AI Components shows it).

## What it would take later

1. Aion Instruct documented with a context window that holds a chunk prompt plus reply (today about 5,000-9,000 tokens; or a re-designed shorter chunk, which is a summary-pipeline change measured with `sum-eval`).
2. Package identity for the NSIS install (packaging with external location, `systemAIModels` capability, a production signing certificate) and, for Phi Silica only, a LAF token.
3. A quality run with `cargo xtask sum-eval` on the dev meetings against the 4B (non-deterministic output: no seed control, so repeated runs and a looser reproducibility rule).
4. A telemetry check like `cargo xtask qnn-etw` for the Windows AI components (Microsoft documents that prompts and outputs stay on the device; diagnostic data is not documented).
5. A fallback to llama.cpp for chunks blocked by the always-on content moderation.

## Verdict

**Not feasible for Earshot as the summary engine today.** At best it is a future option that would need packaging, terms and a different model to be re-evaluated in 2027.

Blocking conditions, roughly in order of severity:

1. **The context window is too small for our chunk sizes.** Microsoft's platform card states "approximately 3.5K tokens", and the best-practices page says that window is *shared* by the system prompt, the prompt and the generated response. Earshot's chunk prompt alone is ~3,500-5,500 tokens (2,000-4,000 transcript plus ~1,500 instructions), with replies of up to a few thousand tokens. To fit, chunks would have to be cut to a few minutes of transcript each, with a much shorter instruction block and reply. That is a redesign of the summary pipeline, not a backend swap.
2. **Phi Silica is being removed.** Learn (phi-silica page, 2026-10-16) says Aion Instruct begins rolling out to Insider devices in November 2026 and to retail devices in January 2027, "and Phi Silica is removed". Any work done now would target a model that is gone within about 2 months. Aion Instruct's context size, quality and JSON support are not documented on Learn (UNCONFIRMED).
3. **A Limited Access Feature (LAF) token is required for production use of Phi Silica.** It comes from Microsoft through a request form. The no-LAF route is the Windows App SDK *experimental* channel, which Microsoft says is not supported in production and cannot ship in the Store. Microsoft says Aion Instruct will not need a LAF token.
4. **Package identity is required.** Earshot is an unpackaged NSIS install. It would need a signed identity package ("packaging with external location") declaring the `systemAIModels` capability, registered by the installer, a production code-signing certificate, a side-by-side manifest in the exe, the Windows App SDK runtime deployed to the machine, and a call to the Bootstrapper API at startup.
5. **Content moderation cannot be fully turned off.** "High" severity content (level 3 and above) is always blocked, for both prompt and response. A meeting that discusses violence, self-harm, harassment or similar topics in earnest can make a chunk fail with `PromptBlockedByContentModeration` / `ResponseBlockedByContentModeration`. That chunk then needs a fallback (llama.cpp).
6. **Output is altered.** Since October 2026, `GenerateResponseAsync` output carries an invisible watermark: one or more `U+200B U+034F U+2060 U+200B` sequences inserted at positions chosen by heuristic, including inside JSON. Whether `GenerateStructuredJsonResponseAsync` is watermarked is UNCONFIRMED: it is not in Microsoft's list of affected APIs.

Not blocking, but notable: for inference Microsoft states that prompts and outputs stay on the device, which is compatible with Earshot's privacy rule. Structured JSON output exists (`GenerateStructuredJsonResponseAsync`, Windows App SDK 2.0). It is a WinRT API, so Rust can call it in principle through windows-bindgen over the Windows App SDK metadata.

If the owner still wants an NPU summary path, the realistic order is: (a) wait for Aion Instruct's documented context size and API terms (early 2027), then (b) prototype in a small packaged C++/C# helper or a windows-bindgen crate, behind the existing `Generate` trait, with llama.cpp kept as the fallback.

## 1. Availability

- **Windows App SDK versions.** The `LanguageModel` class reference lists the monikers windows-app-sdk-1.7, 1.8, 2.0-experimental and 2.0 ([LanguageModel class](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.ai.text.languagemodel), updated 2026-09-30). The APIs overview says Phi Silica as a Limited Access Feature arrived in stable **1.8.0 (1.8.250907003)**. Phi Silica on GPU needs **2.2.2-experimental9** (June 2026 Experimental) ([What are Windows AI APIs?](https://learn.microsoft.com/en-us/windows/ai/apis/), ms.date 2026-10-08). The get-started page tells developers to pick a stable SDK "such as 2.5.1 or later" ([Get started](https://learn.microsoft.com/en-us/windows/ai/apis/get-started), ms.date 2026-10-14).
- **Windows version.** "Windows 11, version 25H2 (build 10.0.26200.7309) or later must be installed on the Copilot+ PC" ([Troubleshooting](https://learn.microsoft.com/en-us/windows/ai/apis/troubleshooting), ms.date 2025-12-15, updated 2026-07-09). The app manifest's `MaxVersionTested` must be at least 10.0.26226.0 ([Get started](https://learn.microsoft.com/en-us/windows/ai/apis/get-started)).
- **Hardware.** Phi Silica runs on the NPU of a Copilot+ PC, or on supported NVIDIA/AMD GPUs (6+ GB VRAM) on non-Copilot+ PCs. GPU use needs Developer Mode, an Insider Experimental build and the experimental SDK. CPU is "Not supported". "On a Copilot+ PC, supported APIs always run on the NPU" ([What are Windows AI APIs?](https://learn.microsoft.com/en-us/windows/ai/apis/)). On Copilot+ PCs the NPU model is preinstalled; on GPU devices it is downloaded on demand ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica), ms.date 2026-10-16).
- **ARM64 / Snapdragon X2 Elite.** The Copilot+ developer guide lists "Microsoft Surface Pro Copilot+ PC" and Snapdragon X Elite devices generically ([Copilot+ PCs developer guide](https://learn.microsoft.com/en-us/windows/ai/npu-devices/), ms.date 2025-11-17). The get-started page shows building for ARM64. Snapdragon **X2** Elite is not named on any page read: UNCONFIRMED. It can be checked on the device under Settings > System > AI Components, or with the AI Dev Gallery Phi Silica sample (the troubleshooting page's check).
- **Region and language.** "Phi Silica features are not available in China" ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica)). On language, the transparency note says only "Performance may vary across languages, and some languages may not be supported" ([Transparency note](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica-transparency-note), ms.date 2026-05-26). English support is not stated explicitly: UNCONFIRMED, though it is almost certainly the primary language.
- **Replacement.** "Phi Silica is being replaced by Aion Instruct... November 2026: Aion Instruct begins rolling out to Windows Insider Preview devices... January 2027: Aion Instruct rolls out to retail devices and Phi Silica is removed." The active model is chosen by a Windows Controlled Feature Rollout ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica)). Whether Aion Instruct keeps the same `LanguageModel` API surface, context size and JSON support is UNCONFIRMED. The June 2026 Edge blog describes Aion-1.0-Instruct only for Edge's Prompt API, with no size or context figures ([Edge blog, 2026-06-02](https://blogs.windows.com/msedgedev/2026/06/02/expanding-on-device-ai-in-microsoft-edge-new-models-and-apis-for-the-web/)).

## 2. Access requirements

- **Package identity: required.** "Apps that use Windows AI APIs need to be granted package identity at runtime... If you are seeing an UnauthorizedAccessException... ensure that your app is packaged and the systemAIModels capability was added to your manifest file" ([Troubleshooting](https://learn.microsoft.com/en-us/windows/ai/apis/troubleshooting)). Packaging with external location (sparse package) is explicitly listed as unlocking "Windows AI Foundry APIs" for unpackaged Win32 apps without changing the installer ([Grant package identity by packaging with external location](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps), ms.date 2026-10-03). Microsoft's Electron guide uses exactly this route: a sparse identity plus `<systemai:Capability Name="systemAIModels"/>` ([Electron Phi Silica addon](https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/guides/electron-phi-silica-addon), ms.date 2026-10-14).
  - What an NSIS install would need: an identity MSIX manifest (`AllowExternalContent`, `runFullTrust`, `TrustLevel="mediumIL"`, `RuntimeBehavior="win32App"`, plus the `systemai` capability), built with MakeAppx and **signed with a certificate trusted on the target** ("a production certificate ... will be required to register the package on end user computers"), an `<msix>` element in the exe's side-by-side manifest, and registration in the installer (`Add-AppxPackage -ExternalLocation` or `PackageManager.AddPackageByUriAsync`), with unregistration on uninstall ([same page](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps)).
- **Limited Access Feature: required for Phi Silica.** "The Phi Silica APIs are part of a Limited Access Feature... to request an unlock token, please use the LAF Access Token Request Form" ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica)). The troubleshooting page says experimental releases do not require LAF tokens, but also that experimental features "are not supported for use in production environments and apps that use them cannot be published to the Microsoft Store" ([Troubleshooting](https://learn.microsoft.com/en-us/windows/ai/apis/troubleshooting)). "Unlike Phi Silica, LAF tokens are no longer needed with Aion Instruct" ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica)). The approval criteria, turnaround and conditions attached to a LAF token are not on Learn: UNCONFIRMED.
- **Readiness and model download.** Call `GetReadyState`. If `NotReady`, call `EnsureReadyAsync`, which installs the model through Windows Update in the background. `NotSupportedOnCurrentSystem` means the device cannot run it. `DisabledByUser` means the user removed or disabled the AI component ([Get started](https://learn.microsoft.com/en-us/windows/ai/apis/get-started)). On Copilot+ PCs the NPU model is preinstalled and "managed by the system". Windows "may temporarily unload the model" under memory pressure ([Platform card](https://learn.microsoft.com/en-us/windows/ai/cards/phi-silica-platform-card), ms.date 2026-10-08). Windows Update must not be paused ([Troubleshooting](https://learn.microsoft.com/en-us/windows/ai/apis/troubleshooting)).
- **Policy.** `LanguageModelResponseStatus.BlockedByPolicy` exists ("Generative AI blocked by system policy") ([Best practices](https://learn.microsoft.com/en-us/windows/ai/apis/language-model-best-practices), ms.date 2026-03-26), so managed devices can turn the feature off.

## 3. Calling it from Rust

- **It is a WinRT API shipped in the Windows App SDK, not in the OS SDK metadata.** `Microsoft.Windows.AI.Text.LanguageModel` carries WinRT attributes (`ContractVersion(LanguageModelContract)`, `MarshalingBehavior(Agile)`, `IClosable`) and is documented under the Windows App SDK API reference ([LanguageModel class](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.ai.text.languagemodel)). The `windows` crate's bundled metadata covers Win32 and the OS WinRT surface. windows-bindgen can generate bindings from a custom `.winmd` via `.input("component.winmd")` (plus `.input_default()` for Windows types) ([windows-bindgen readme](https://github.com/microsoft/windows-rs/blob/master/crates/libs/bindgen/readme.md)). Microsoft has no Rust guide for these APIs. Generating bindings from the Windows App SDK `Microsoft.Windows.AI*.winmd` files is plausible but UNCONFIRMED. The old `windows-app` crate (Rust bootstrapping for the Windows App SDK) is archived.
- **Runtime requirements for an unpackaged or externally located app** ([Deployment guide for apps packaged with external location or unpackaged](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/deploy-unpackaged-apps), ms.date 2026-05-29):
  - The app is "responsible for deploying required Windows App SDK runtime packages": run `WindowsAppRuntimeInstall.exe --quiet` (per architecture, Arm64 included) chained from the installer, or install the MSIX packages directly.
  - The app "must call the Bootstrapper API" (`MddBootstrapInitialize2` in `Microsoft.WindowsAppRuntime.Bootstrap.dll`) before using Windows App SDK features. This adds the framework package to the process's package graph and starts the DDLM.
  - The Visual C++ Redistributable is a prerequisite. Microsoft recommends deploying the `.winmd` files with the app.
- **Microsoft's own non-.NET example** wraps the call in a C# Native AOT addon (or C++ via node-addon-api) and gives the host a sparse debug identity ([Electron Phi Silica addon](https://learn.microsoft.com/en-us/windows/apps/dev-tools/winapp-cli/guides/electron-phi-silica-addon)). For Earshot, the equivalent would be a windows-bindgen crate or a small C++/WinRT DLL called from Rust, plus the bootstrapper and identity package above.
- **Purity contract.** All of this would live in a new adapter crate (unsafe FFI, Windows only), never in `earshot-core`.

## 4. Capabilities

- **Context length.** "Phi Silica supports a relatively small token window: approximately 3.5K tokens... When inputs exceed the token limit, the model may truncate content or generate incomplete responses" ([Platform card](https://learn.microsoft.com/en-us/windows/ai/cards/phi-silica-platform-card), 2026-10-08). The window "is shared by the system prompt, all accumulated conversation history (prior prompts and responses), and the current prompt". `GetUsablePromptLength` returns the character index where the prompt stops fitting, and a too-long prompt gives `PromptLargerThanContext` ([Best practices](https://learn.microsoft.com/en-us/windows/ai/apis/language-model-best-practices)). The December 2024 launch blog said 2k context with 4k "coming shortly" ([Windows Experience blog, 2024-12-06](https://blogs.windows.com/windowsexperience/2024/12/06/phi-silica-small-but-mighty-on-device-slm/)). "Prompt compression" on the NPU "enables longer effective context windows" ([Transparency note](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica-transparency-note)); how much longer is UNCONFIRMED.
- **Maximum output length.** No separate figure is documented, and there is no max-tokens option: UNCONFIRMED. The output shares the ~3.5K window.
- **System prompt.** Yes: `CreateContext(systemPrompt)` returns a `LanguageModelContext`, which is passed to `GenerateResponseAsync(context, prompt, options)`. The context accumulates history in place ([Best practices](https://learn.microsoft.com/en-us/windows/ai/apis/language-model-best-practices)). Whether `GenerateStructuredJsonResponseAsync` accepts a context or system prompt is UNCONFIRMED: its overloads take only `(prompt, jsonSchema[, options])`.
- **Structured output.** `GenerateStructuredJsonResponseAsync(prompt, jsonSchema[, options])` "generates a language model response constrained to a caller-supplied JSON schema". It is available only in Windows App SDK 2.0 / 2.0-experimental ([method reference](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.ai.text.languagemodel.generatestructuredjsonresponseasync), updated 2026-09-30). The supported JSON Schema subset, and whether our `schemas/summary-llm.v1.json` is accepted, are UNCONFIRMED. There is no GBNF or grammar API.
- **Sampling options.** `LanguageModelOptions` has `Temperature` (default 0.9), `TopP` (0.9), `TopK` (40), `ContentFilterOptions` and `LowRankAdapter` (LoRA) ([LanguageModelOptions](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.ai.text.languagemodeloptions), [Best practices](https://learn.microsoft.com/en-us/windows/ai/apis/language-model-best-practices)). There is no seed: "The API assigns a new random seed on each call". Even Temperature 0 with TopK 1 is not guaranteed deterministic across hardware or model updates. This matters for our reproducibility rules: sum-eval results would not be reproducible.
- **Streaming.** Yes: the generate methods return `IAsyncOperationWithProgress` with partial text as progress ([LanguageModel](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.windows.ai.text.languagemodel)). Streaming has "modest overhead" because moderation runs more often ([Platform card](https://learn.microsoft.com/en-us/windows/ai/cards/phi-silica-platform-card)).
- **Built-in summariser.** `TextSummarizer` (`SummarizeAsync`, `SummarizeConversationAsync`, `SummarizeParagraphAsync`) exists ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica), [Watermarking](https://learn.microsoft.com/en-us/windows/ai/apis/text-watermarking)). It returns free text, not our schema with segment citations, so it does not replace our structured summary.
- **Content moderation.** It is on by default for prompt and response across four categories (hate, sexual, violence, self-harm). The default is `medium` (severity 0-3 returned). `high` is "Not available. Content classified as severity level 3+ ... is currently blocked" ([Content moderation](https://learn.microsoft.com/en-us/windows/ai/apis/content-moderation), ms.date 2026-06-18). The platform card adds "the system ensures high-risk content is not returned even when filters are adjusted" and warns it "may occasionally flag or block content when the text resembles topics associated with sensitive categories". A blocked call returns `PromptBlockedByContentModeration` or `ResponseBlockedByContentModeration`, and the context state is then unspecified ([Best practices](https://learn.microsoft.com/en-us/windows/ai/apis/language-model-best-practices)). So it can **block** a chunk; the docs do not say it **rewrites** text. It is configurable only within the levels above and cannot be switched off.
- **Watermark.** From October 2026, `GenerateResponseAsync`, `GenerateResponseFromEmbeddingsAsync` and the TextRewriter/TextSummarizer methods insert zero or more invisible `U+200B U+034F U+2060 U+200B` sequences. Microsoft warns this affects "Generating JSON and then parsing it" and puts the responsibility for AI-content marking on the app ([Watermarking](https://learn.microsoft.com/en-us/windows/ai/apis/text-watermarking), ms.date 2026-10-16). `GenerateStructuredJsonResponseAsync` is not in the list (UNCONFIRMED whether it is exempt).

## 5. Privacy and telemetry

- **Inference content stays local (documented).** "Phi Silica processes all prompts and generates all responses locally on the user's device. No user prompts or model outputs are transmitted to Microsoft or any third party during inference" ([Transparency note](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica-transparency-note)). "Windows AI APIs process data locally on the device using the NPU. Input data is not sent to Microsoft servers" ([Windows AI FAQ](https://learn.microsoft.com/en-us/windows/ai/faq), ms.date 2026-05-10). "Because the model runs entirely on-device, user inputs and outputs remain local" ([Platform card](https://learn.microsoft.com/en-us/windows/ai/cards/phi-silica-platform-card)).
- **Diagnostic or usage telemetry.** No Learn page read describes what Windows diagnostic data (if any) the Windows AI APIs, the content-moderation classifiers or the LAF check emit, for example usage counts, moderation trigger rates or token counts: UNCONFIRMED. Under Earshot's rule this would need the same treatment as T8.3b (an ETW capture with a no-transcript-text check), since the API runs inside Windows components outside our control.
- **Network side effects.** `EnsureReadyAsync` installs through Windows Update (an OS channel, not one of ours). LAF validation is described as a token check; whether it involves any network call is UNCONFIRMED.
- **Fit with the rule.** The documented behaviour (content never leaves the device; system-level Windows telemetry possible) is compatible with the owner's rule, pending the telemetry check above.

## 7. Published quality and speed figures

- **Speed (Snapdragon X Elite, December 2024 model):** time to first token 230 ms for short prompts, throughput "up to 20 tokens/s", prompts processed in 64-token chunks, 4-bit weights (QuaRot + GPTQ), derived from Phi-3.5-mini ([Windows Experience blog, 2024-12-06](https://blogs.windows.com/windowsexperience/2024/12/06/phi-silica-small-but-mighty-on-device-slm/)). Speculative decoding has since been added on the NPU ([Phi Silica](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica)), so current throughput may be higher: UNCONFIRMED, as no newer official number was found. Nothing is published for Snapdragon X2 Elite: UNCONFIRMED.
- **Quality:** "Phi Silica does not have publicly released evaluation metrics" ([Platform card](https://learn.microsoft.com/en-us/windows/ai/cards/phi-silica-platform-card)). The 2024 blog gives only float vs 4-bit zero-shot deltas (for example arc_easy 85.69 -> 82.74, MMLU college CS 57.00 -> 48.00), with no comparison against Phi-3 or Phi-4-mini. A head-to-head against our Qwen 3.5 4B/9B on the AMI sum-eval set would have to be measured ourselves.
- **Rough fit estimate (not from Microsoft):** at ~20 tokens/s, a 1,500-token reply takes ~75 s per chunk before prompt processing. That would only beat the Surface CPU path if prompt processing on the NPU is much faster. This would need measuring on the device.
