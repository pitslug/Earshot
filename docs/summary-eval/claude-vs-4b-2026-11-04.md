# Claude through Claude Code against Qwen 3.5 4B (T7.4gb, 2026-11-04)

The owner asked how quick and how good a Claude summary is next to the 4B. Report only: no default changes.

## Setup

- **Meetings.** The five judged dev meetings of T6.20e: ES2003c, ES2011c, IS1008c, TS3004c, TS3006c, AMI reference transcripts (`--source reference`, public text only).
- **Prompt.** The production prompt (T6.20f `settled` rules, format key `indented-numbered-r5`).
- **Qwen 3.5 4B.** Surface Pro (Snapdragon X2 Elite), processor, 6 threads, nothing else running, the production plan: 600 s chunks then a combine step. "After hang-up" is the whole run; "chunks during the meeting" is the wait if the earlier chunks were summarised while recording (last chunk plus the combine step, as T8.3l).
- **Claude through Claude Code.** The production T7.4ga path (Claude Code 2.1.318, its default model, the owner's claude.ai sign-in, no tools or settings). "Whole meeting" is the production plan for this provider: one request per meeting (each fits the 200k budget). "Chunked" forces 600 s chunks and a combine step, for comparison with live summaries.
- **Commands.** `cargo xtask sum-eval --backend cpu --split dev --source reference --model qwen3.5-4b-q4_k_m --chunk-seconds 600 --threads 6 --meeting <5> --out target/sum-eval/t74gb-4b`; `cargo xtask sum-eval --model claude-code --split dev --source reference --meeting <5> --out target/sum-eval/t74gb-claude-code`; the same with `--chunk-seconds 600 --out target/sum-eval/t74gb-claude-code-chunk600`.
- **Judging.** The fixed real-item lists and rules of docs/summary-eval/prompt-rounds-2026-11-04.md (42 real decisions, 18 real actions). One Claude Code judge per meeting read the transcript, the fixed list and the three summaries labelled A, B and C, shuffled per meeting; the key stayed with the coordinator until every verdict was in. These are new judges, not the T6.20e ones, so counts are comparable within this report, not exactly with T6.20e's rows. The judges are Claude models judging partly Claude output; the blinding is the guard against that.

## Reading

- **Speed.** Claude on the whole meeting is ready 27 to 39 s after hang-up, against 9 to 23 minutes for the 4B on the Surface processor (4.5 to 8.7 minutes with chunks during the meeting). Chunking does not help Claude: its combine step costs more than one large request.
- **Quality.** Claude caught 37 of 42 decisions and 17 of 18 actions on the whole meeting (35 and 18 chunked) with nothing made up; the 4B caught 28 and 12 with 15 made up. The made-up count is the clearest difference: Claude wrote no invented or premature item in 10 summaries.
- **Trade-off.** Claude sends the meeting text to Anthropic (the PLAN 3.9 agent-CLI exception, opt-in) and needs Claude Code signed in; the 4B keeps everything on the computer.
- **Caveats.** Five meetings, one run each; judges are Claude models, blinded; one owner call is ambiguous in the transcript (ES2003c A3, physical make-up, given to the User Interface Designer by one Claude summary and judged wrong by the list).
