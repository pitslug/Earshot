# AGENTS.md - How to build Earshot

You are building Earshot with the owner in interactive sessions. Everything you need is in this file and `PLAN.md` (what to build, task list). The session log and the hardware gates are kept privately by the owner and are never in this repo: `LOG.md` and `gates/` below mean those private copies, `cargo xtask public-guard` refuses them here, and a contributor without them skips those steps and reports in the pull request. On the owner's machine they sit in this folder, ignored by git (the "Private files" block of `.gitignore`), and are still kept up to date. This folder is the one public repo: there is no separate private copy to keep in step.

Read this file at the start of every session.

---

## 1. Ground rules

1. **The task list in PLAN.md section 8 is the work queue.** Work through it in order, one task at a time, one commit per task. If something is missing, add a task (6.3) instead of doing it silently.
2. **Scope of a session** is whatever the owner asks for ("do T1.4", "finish M2", "keep going"). Keep going through tasks until that scope is done, a gate is reached, or you need a decision. Then stop and report.
3. **Gates are hard stops.** When the next task is a gate, prepare it (section 4) and wait for the owner. Never treat a gate as passed because tests pass on the build host.
4. **Never weaken a test to make it pass.** No loosening thresholds, deleting or `#[ignore]`-ing failing tests, editing fixture checksums, shrinking fixture sets, or special-casing fixture inputs. If a target looks unreachable, stop and ask.
5. **Evidence before claims.** A task is `[x]` only after its `accept` command passed in this session and you saw the output.
6. **Respect the core purity contract** (PLAN.md 3.2). If a design needs OS access in `earshot-core`, put a trait in core and the implementation in an adapter crate.
7. **Privacy invariants** (PLAN.md 3.9) are requirements, not preferences. The owner's rule (2026-10-24): the content of their conversations (audio, transcripts, summaries, names, prompts) never leaves the device except text to the LLM endpoint they configured. Earshot sends no telemetry of its own; system-information telemetry that third-party runtimes offer to Windows (versions, hardware, drivers) is accepted. No new network destinations (the update host, D24, was agreed by the owner and is chosen by them in T9.1b).
8. **Do not install system software** (MSVC, CUDA, Android Studio, Docker, drivers). You may run `rustup target add`, `rustup component add`, `cargo install <dev tool>` and `pnpm install`. For anything else, tell the owner exactly what to install.
9. **Never commit** models, large audio, secrets, API keys, `fixtures/private/`, or files over 5 MB.
10. **Do not push** to any remote unless the owner asks. Everything committed here becomes public, commit messages included: no name, date or phrase from a real recording or meeting, and no private measurement. A new private file joins the "Private files" block of `.gitignore` before anything stages it.
11. **The project's own code is MIT** (`LICENSE`). Do not change licensing. Never add a dependency that would put the whole under copyleft terms: NVIDIA's EULA 1.2 item 5 forbids that for files with its runtime linked in (docs/cuda-libraries.md).
12. **No em dashes** in generated Markdown, UI copy, commit messages or log entries. Use hyphens, parentheses, colons or "->". Exception: test inputs and goldens that exist to test em-dash handling (e.g. the export `replace_em_dash` option or preserving a user's own text) may contain them.

## 2. Session start

1. Read `PLAN.md` section 8 and, if you have them, the last few entries of the private log and the private gate notes.
2. Run `git status` and `git log --oneline -5`. If the tree is dirty or a task is marked `[~]`, tell the owner what you found before touching it. Never `git reset --hard` or discard uncommitted work.
3. If a `wip/<task-id>` branch exists, that task was stopped mid-way; resume from it when the task comes up.
4. Once T0.2 exists, run `cargo xtask doctor` if the host may have changed, and note the host in the log.
5. Tell the owner the next eligible task (or the open gate) in one line, unless the owner has already said what to do.

## 3. Working a task

### 3.1 Pick
Take the **first** entry in PLAN.md section 8, in document order, with status `[ ]` and every dep marked `[x]`. If the owner names a task, do that one, but say so if its deps are not done. If the entry is a gate, go to section 4.

### 3.2 Claim
Set it to `[~]` in PLAN.md.

### 3.3 Do
- Read the relevant PLAN.md sections (architecture, thresholds, decisions) before designing anything.
- Test-driven: write the failing test from the task's `accept` criteria first, then implement.
- You may use subagents for exploring, implementing, validating and reviewing. You stay responsible: read their reports and check the diff.
- Stay within the task. Note unrelated problems as new tasks (6.3).
- Use `cargo xtask` for build/test/accept so commands are identical on every host. The host shell is PowerShell; prefer Rust in xtask over shell scripts.
- If a task is clearly too large (more than roughly 2 hours of work or ~800 changed lines), propose a split into `T<m>.<n>a`, `T<m>.<n>b`, ... each with its own `accept` command.

### 3.4 Verify
1. The task's `accept` command.
2. `cargo xtask ci` (fmt, clippy -D warnings, tests, purity) once T0.2 exists.
3. A validator run (validator subagent, or yourself for trivial tasks) confirming the `accept` and `ci` results independently of the implementer's report.
4. A self-review of the diff against the task's `do` text, the purity contract and the ground rules.
5. An independent review (reviewer subagent) when the review policy in 3.5 requires one. Resolve its findings before committing.

### 3.5 Review policy
This overrides any default of reviewing every diff. The main risk being guarded against is a test, metric or threshold quietly bent to pass, so reviewers must read the test and harness code, not just the implementation.

| When | Review |
|---|---|
| Every task | `accept` + `ci` + validator. No reviewer unless listed below. |
| Merging a parallel worktree lane into `main` | Reviewer on the lane's combined diff, before the merge commit. |
| Every milestone acceptance task (T1.6, T2.5, T3.5, T4.5, T5.5, T6.6, T7.6, T10.6, T11.4) | Reviewer focused on harness honesty: metrics computed correctly, no fixture special-casing, thresholds read from `acceptance/thresholds.toml` unchanged. |
| Always, per task | T0.2 (acceptance framework), T0.3 (purity guard), T0.5 (metrics), T5.1 and T5.2 (data model, migrations), T6.2a and T6.2b (pipeline state machine), T6.3 and T10.3 (unsafe FFI: WASAPI, JNI), T4.3, T9.1b and all of M11 (network code, privacy). |

If a reviewer finds a gamed test or a purity or privacy violation in an unreviewed task, review the rest of that lane or milestone too.

### 3.6 Finish
- **Pass:** set the task to `[x]`, add an entry to the private log (section 7), commit the work (section 8). If it completed a milestone, add a short summary to the private log and create a local tag `m<N>`.
- **Fail and you can see the fix:** keep going.
- **Stuck** (several honest attempts, or anything in 5): set it back to `[ ]`, log what was tried with the measured numbers, and ask the owner.
- **Session ending mid-task:** commit work-in-progress on `wip/<task-id>` (never on `main`), set the task back to `[ ]`, log where you stopped.

### 3.7 Parallel lanes (git worktrees)
When the owner asks for parallel work, independent tasks run as lanes, each in its own git worktree and branch (`lane/<name>`):
- A lane works its tasks in PLAN.md order, one commit per task on its branch, using the commit format in section 8.
- Lanes never edit `PLAN.md`, `LOG.md`, `AGENTS.md` or `TODO.md`. They report results, accept output and `Learned for AGENTS.md` bullets instead; the coordinator applies them on `main`.
- Lanes must not start a task whose deps are not `[x]` on `main` or earlier in the same lane.
- The coordinator merges one lane at a time into `main` (`git merge --no-ff lane/<name>`), resolves conflicts, runs `cargo xtask ci` and the lane's accept commands on `main`, gets the lane-merge review (3.5), then updates PLAN.md and LOG.md in the merge commit.

## 4. Gates

When the next entry is a gate:

1. Build every artefact you can beforehand.
2. Write the gate's notes, in the private gate folder and never in this repo: **why** (what it verifies, what waits on it), **prerequisites** (hardware, builds with exact paths), **steps** (numbered PowerShell commands, one per code block, with what to look or listen for), **pass criteria** (from PLAN.md section 5 and the gate's entry).
3. Tell the owner it is ready.
4. The owner reports back in chat. Record the result verbatim in the private gate folder.
   - **Pass:** mark the gate `[x]`, turn any follow-ups into tasks.
   - **Fail:** add fix tasks before the gate (6.3); the gate is re-run after them.
5. Conditional gates (GATE-00, GATE-05): run the check first. If everything is present, record the doctor output as the `.pass` file and carry on; otherwise give the owner the exact install list.

## 5. Stop and ask when

- A threshold looks unreachable without loosening it.
- A licence for a fixture, model or dependency is unclear or non-permissive.
- A system toolchain is missing.
- The plan contradicts itself or reality (an API does not exist, a crate is abandoned, a model is unavailable).
- The work would break a ground rule or privacy invariant.

Record the question and the owner's answer in LOG.md, and update PLAN.md sections 6/7 if it changes a decision.

## 11. Validation notes, invariants, conventions

Rules learned while building. One bullet per rule; history lives in commits.

### Validation notes
- `cargo test -p xtask --test thresholds` checks the shape of `acceptance/thresholds.toml` and that its ids match PLAN.md 4.2. It does not pin numeric values, so tightening a threshold needs no test edit.
- `cargo xtask accept m0` checks `acceptance/thresholds.toml` against every PLAN.md 4.2 row (milestone, op, value, unit where the table gives one, provisional). Changing a value in one file but not the other fails m0, so a tightening edits both files in the same commit.
- `cargo xtask accept <m>` rewrites `acceptance/results/<m>.json` on every run; commit it with the task.
- `cargo xtask purity` runs: (1) no `build.rs` in core; (2) `#![forbid(unsafe_code)]` on its own line in core `src/lib.rs`; (3) `cargo build -p earshot-core --lib --target wasm32-unknown-unknown`; (4) the ban list over `cargo tree -p earshot-core -e normal --target all`; also source scans refusing `#[path]` / `include!` and every form of the clippy cfg in core `src/`; (5) a native-builder ban (`purity::NATIVE_BUILDERS`) over `cargo tree -e normal,build --target all` (`-e build` alone does not follow normal edges); (6) `cargo clippy -p earshot-core --lib -- -D warnings -F clippy::disallowed_methods -F clippy::disallowed_types -F unsafe_code` with `CLIPPY_CONF_DIR` pinned to `crates/earshot-core`. `cargo test -p xtask --lib purity` runs canaries on temp-dir crates (needs the pinned clippy and wasm32 target, no network).
- trybuild snapshots in `crates/earshot-core/tests/ui/*.stderr` are tied to the pinned toolchain; regenerate with `TRYBUILD=overwrite` only after a toolchain bump, and review the diff.
- Run `cargo xtask` from the repo root: the alias's `--target-dir target/xtask` is relative to the current directory.
- `cargo test -p xtask fixtures` checks the committed subset, smoke and AMI metadata without network; test names in that module must contain `fixtures`. `--verify` re-hashes archives and committed files, re-derives the LibriSpeech subset from the corpus, and re-hashes every extracted file recorded in the extraction marker (`.earshot-extracted`: line 1 the archive SHA-256, then `<sha256> <size> <path>` per file); a mismatch, an unrecorded file or a marker without file lines re-extracts.

### Invariants
- Adding or removing a row in PLAN.md 4.2 requires changing `acceptance/thresholds.toml` and `EXPECTED_IDS` in `xtask/src/thresholds.rs` in the same commit.
- The core purity contract applies to the `earshot-core` lib target and its normal dependencies; core tests may read fixtures (read-only) from `EARSHOT_FIXTURES`.
- Open-set match thresholds (voiceprints) are fixed on a dev split, never tuned on the acceptance set.
- All HTTP in shipped crates goes through `earshot-net`. The ci `net` step (`xtask/src/net_guard.rs`) fails if a crate in `HTTP_CLIENT_CRATES` appears in any non-xtask member's normal dependency graph outside the `earshot-net` subtree; adding any crate that can speak HTTP means adding its name there. (PLAN 3.9 still names a clippy rule; the cargo-tree step is what is implemented, pending the owner's confirmation of the wording.)
- `earshot-net` follows redirects itself: every hop passes `Allowlist::check` and produces exactly one `AuditEntry`; on a cross-origin hop no caller header is forwarded except `Content-Type` while a 307/308 body is forwarded. Never re-enable reqwest's redirects, retries or system proxy.
- Never put a `reqwest::Error` or a raw URL into an error, log or audit entry: build `NetError::Transport` only through `client::transport()` (strips the URL) and print URLs only through `redact()` (drops userinfo, query, fragment).
- `NetClient` buffers responses up to `NetConfig::max_body` (default 64 MiB) and applies `DEFAULT_TIMEOUT` (600 s) per hop when a request sets none; large model downloads need a streaming API in `earshot-net`, not a bigger limit. Callers need a tokio runtime context; add tokio as a dev-dependency with `default-features = false`, never as a normal dependency of core.
- `schemas/summary.v1.json` is generated from `earshot_core::summary`; change it only with `cargo xtask schema --write` in the same commit as the type change (ci step `schema` fails on byte drift). Nullable summary fields stay in `required` for strict structured outputs: `Option<T>` without `serde(default)` plus `#[schemars(with = ...)]` to a nullable schema type; never `#[schemars(required)]`. `summary::validate` keeps one field list per object, pinned to the schema by `summary_validator_field_lists_match_the_schema`. Doc comments on summary types become schema `description`s the LLM reads; put implementation notes in `//` comments. Enabling `serde_json/preserve_order` anywhere would change the generated schema.
- Every milestone runner registers in `REGISTRY` in `xtask/src/accept/mod.rs` and emits exactly one `Measurement` per threshold id of its milestone, with the threshold's unit (`""` for `pass`). Missing, duplicate, extra, non-finite or unit-mismatched measurements fail.
- `--backend` is recorded as `requested_backend` and never changes which thresholds are selected.
- Tests that need fetchable models or fixtures (anything in `models/manifest.toml` or `fixtures/manifest.toml`) FAIL when they are missing, with the `cargo xtask fetch-models` / `fetch-fixtures` instruction in the message; a missing precondition is never a silent skip. Only optional private data (`fixtures/private/`) used for informational output may be skipped, and the skip must be visible in the report. A test over `fixtures/private/` that asserts anything is `#[ignore = "..."]`d (a visible skip), never an early `return`, and is run with `-- --ignored` on the host that has the data.
- whisper-rs and whisper-rs-sys are pinned with `=` (whisper-rs-sys vendors whisper.cpp); upgrading changes both pins and the versions recorded in PLAN D13. whisper-rs-sys forwards every `CMAKE_*`, `GGML_*` and `WHISPER_*` env var to whisper.cpp's CMake without a rebuild trigger: after changing one (e.g. `CMAKE_CUDA_ARCHITECTURES` in `.cargo/config.toml` `[env]`), run `cargo clean -p whisper-rs-sys`. A cold `--features cuda` build takes about 4 minutes; the default build and `cargo xtask ci` never need CUDA.
- Whisper tests prove which backend ran from whisper.cpp's own log (`whisper_backend_init_gpu: no GPU found` for CPU, the CUDA backend and `CUDA0 total size` lines for CUDA), captured via whisper-rs `log_backend`; each log-capturing test is its own integration-test binary because the logger is process-wide.
- whisper-rs 0.16 `FullParams::set_language` / `set_initial_prompt` leak a C string per call: build params once per (language, decoding) and clone them; pass prompts with `set_tokens`. whisper-rs `WhisperContext::tokenize` is unsound when the buffer is too small: always pass `max_tokens >= text.len()`. whisper.cpp falls back to CPU (only logging `whisper_backend_init_gpu: failed to initialize`) when a selected GPU cannot init, so any acceptance report takes the backend from the whisper log, not from `backend_info()` alone. Multithreaded whisper.cpp CPU runs are not bit-reproducible: determinism tests compare words and times exactly and probabilities with a tolerance (if text ever flaps, use 1 thread rather than widen the assertion).
- Backend evidence for whisper.cpp comes only from `earshot_asr_whisper::evidence` (`load_verified`, `classify_whisper_log`, `check_backend`, and `check_call_log` after every batch call and stream, since each beam call re-creates the state and re-runs GPU init); callers never install their own logger or copy the rule. whisper.cpp 1.8.3 beam search samples with decoder 0's RNG seeded once per state: beam calls run on a fresh state (old one freed first); never share a state between beam calls whose results are compared or reported.
- `accept m2` runs the `asr_eval` example in release (`--features cuda` exactly when `doctor::reports_cuda`) for the base.en metrics (`asr.wer_smoke_base` and `asr.wer_ls_base`, always on the CPU, and `asr.echo_leak`) and `m2_prod` for every production-default metric. Tests, thresholds and the ci model set use only the default models (PLAN D22): the English `[[ladder]]` models and the `summary` LLMs; `cargo test -p xtask models` (`Manifest::non_default_models`) fails if `ci` or `desktop` holds anything else, and the models offered but never tested are in set `choice`. `asr.wer_ami_ihm` references are the AMI manual annotations v1.6.2 words files (read as ISO-8859-1 bytes) with the rules in `examples/asr_eval/refs.rs`, fixed before measuring. `asr.wer_aec_delta` identifies near-end utterances by exact clip length, so smoke speaker 121 clips keep distinct lengths.
- Whisper's temperature fallback runs inside whisper.cpp (`temperature_inc`, `entropy_thold` by token entropy, `logprob_thold`); `DecodingOptions::fallback` is its only source, set on each call's params clone, never in the template cache; live stays greedy (best_of 1). whisper-rs 0.16 leaves best_of at -1 on beam params, so a batch retry is one sampled decoder (a documented deviation from openai/whisper). Fallback counts come only from `WhisperTranscriber::fallback_stats` (encoder-begin per window, zero-token logits call per attempt, counted per window); every asr_eval metric reports them and accept m2 fails without them. Sampled live retries reuse the state's RNG and are history-dependent.
- The final pass decodes each track in VAD speech pieces (`asr::transcribe_in_pieces`, enabled by `backends::post_processor` via `PostProcessor::with_pieces`), never one whole-track whisper call: within one `whisper_full` call whisper.cpp primes every 30 s window with the previous windows' text even with `no_context`, which looped for minutes on a test recording. A piece whose text compression ratio exceeds 2.4 is decoded again without a prompt, then greedily, then dropped and reported (`PostWarning::RepetitionDropped`); keep `final_pass_pieces_gate12_take2` (ignored, private data) passing after any final-pass change.
- Echo removal from "Me" is text de-duplication (`asr::dedupe_echo`, runs of 3+ in-order identical words at the AEC delay +-1 s) plus the final-pass speaker check (`diar::speaker_echo_spans` / `remove_speaker_echo`). An acoustic far-only gate was measured and rejected (it deleted 15-57% of near-end words in double talk). `asr.echo_leak` gates on the canceller-on condition (decided by the coordinator under the owner's delegation); the raw-mic condition is a mandatory informational check; scenarios are selected by fields and truth comes from `SimOutput::far_utterances` / `near_utterances`; design and tuning only on `asr_eval --leak-dev`. Transcript-time rules use live-path (VAD-windowed) word times; long batch decodes of quiet residual audio mistime words by seconds.
- Echo cleaning (`asr::dedupe_echo*`, `diar::speaker_echo_spans`) runs only with an AEC delay lock: `delay: None` removes nothing and every mic speaker is Me. A mic speaker who talks alone >= `min_solo` (500 ms) outside every reference turn's delay window is Me whatever their voice. Speaker-check margins live in `diar::echo::CALIBRATED_SPEAKER_ECHO_MARGINS` keyed by exact model id (CAM++ 0.5, picked on `--leak-dev` by the rule in its `source`); an unknown model is `DiarError::Config`, which the runtime must surface, never skip silently. `accept m2` fails if cleaning in the gating aec condition keeps < `ECHO_NEAR_RECALL_FLOOR_PERCENT` (98%) of near-end words heard, pooled and in double talk alone, and requires a no-echo scenario with far speech (`headphones`).
- `WhisperTranscriber` pads every input shorter than `MIN_INPUT_SAMPLES` (1,800 samples: whisper.cpp 1.8.3 decodes nothing up to 10 mel frames, silently at exactly 10, and its 200-sample reflective pad reads past shorter buffers) with trailing silence; callers never pad themselves. A padded call drops words and segments that start in the padding and clamps those that straddle the input end; it never produces a `start == end` word. A failed whisper state creation leaves no state and the next call creates one (`ensure_state`).
- Every asr_eval live-stream metric (`asr.echo_leak`, `asr.wer_stream_delta`) decodes each stream on a fresh whisper state (`WhisperTranscriber::reset_state()`, eval path only; the runtime never resets), so sampled fallback retries do not depend on earlier streams and the metrics are reproducible run to run.
- AMI scoring for `accept m2` and `model_eval` goes only through `asr_eval/refs.rs` (`load_ami_ihm`, `AmiHeadset::score`) and scores `refs::hypothesis_text(refs::kept_words(..))`: the words production keeps after `drop_non_speech`, per segment, as `Transcription::into_segments` does (since 2026-10-24); a change to the non-speech rule changes the metric and is logged. In `docs/model-eval/cuda.json`, `corpora.ami` is IHM with oracle segments (raw runs in `docs/model-eval/cuda-ami.json`, committed unmodified), `ami_mix_headset` the superseded merged stream; `model_check::QUALITY_ORDER` follows `corpora.ami`.
- `cargo xtask build` adds rustc flags only through `cargo --config build.rustflags`, or appended to `CARGO_ENCODED_RUSTFLAGS` when the shell sets either rustflags variable, even to nothing: a set-but-empty variable makes cargo ignore config-file and `--config` rustflags (measured 2026-11-06). ### Conventions
- Workspace uses edition 2024 and resolver 3. Every crate takes version, edition, rust-version and publish from the workspace and sets `[lints] workspace = true`.
- External dependencies go only in adapter crates and xtask, never in `earshot-core` unless they pass the purity check.
- Follow-ups (advisory review findings) go in `TODO.md` at the repo root, one line each with `file:line`.
- xtask logic lives in its lib target (`xtask/src/lib.rs`); `main.rs` stays a thin clap front end.
- On Windows, invoke pnpm as `cmd /c pnpm ...`.
- Clippy at the pinned 1.99 toolchain denies constant-size `chunks_exact(_mut)` (`chunks_exact_to_as_chunks`) and `% n != 0` checks (`manual_is_multiple_of`); use `as_chunks(_mut)::<N>()` and `is_multiple_of`.
- Every ASR backend implements `asr::Transcriber` as a blocking call that polls the `CancelToken` and reports the `BackendInfo` that actually ran; streaming goes through `asr::StreamingChunker` unless a backend has native streaming; core never spawns ASR threads. Decoding settings come only from `DecodingOptions::LIVE` (greedy, temperature 0) and `DecodingOptions::BATCH` (beam 5, temperature 0); acceptance reports serialise the `TranscribeOptions` and `BackendInfo` used.
- Transcript times are `asr::MeetingTime` (ms from meeting start); `Transcriber` output is buffer-relative and only the chunker or `Transcription::into_segments` shift it to meeting time.
- Every `ChunkerConfig` that passes `validate()` is safe for every VAD pattern (`asr_chunker_every_valid_config_is_safe_for_any_vad_pattern` is the guard; new config fields get edge values there). In `StreamingChunker::step` an utterance end is decided before a `max_window` cut, and `close` clamps its range to the window.
- LocalAgreement never drops words by a hard time floor: committed words are removed by text anchors first and the whisper_streaming 100 ms time rule only as fallback; chunker changes keep the `with_timestamp_jitter` (below overlap/2) test passing. Tokens that normalise to "" never agree or anchor.
- The `EnergyVad` noise floor is the minimum over `min_window` (1.5 s) limited by `floor_rise_db_per_s`; both have guard tests.
- `diar::Embedding` carries an `EmbeddingModelId`; compare embeddings only via `Embedding::cosine_similarity` (errors on model mismatch). `ClusteringConfig.threshold` is a Euclidean distance between un-normalised means of unit embeddings (scipy centroid linkage), so pyannote 3.1's 0.7046 applies unchanged for WeSpeaker; any other embedder is calibrated on dev data (T3.2/T3.5), never on the acceptance set. Pipeline tests run the exact segmenter under flat 1% DER bounds and the jittered segmenter under a jitter-derived no-collar bound; keep both. Diarisation tests score glue DER with `DerConfig::nist(AMI_COLLAR_PER_SIDE_S)` and with no collar; the negative control must keep failing a merged clustering. Diar fakes read ground truth from `scene_audio`; new diar tests build scenes with it.
- `Diarizer::diarize` is `diarize_from` over empty `WindowResults` (one code path, T6.13d1): changes to steps 1-3 keep the batches and embedding flush points of `starts.chunks(batch_size)`, and any new per-window setting goes into `WindowParams`. Keep `diar_stream_then_final_half_equals_the_whole_track_with_the_same_calls` and `diar_stream_stopped_anywhere_resumes_on_a_fresh_diarizer` passing. Tests where a second diarizer resumes another's work use `FakeSegmenter::content_seeded()` / `FakeEmbedder::content_seeded()` (the default fakes depend on call order, which is what proves the same calls in the same order). `WindowResults::from_bytes` returns `DiarError::State` for any damaged, foreign or inconsistent input and never panics; a runtime record wrapping it keeps its own version outside the payload.
- Live speaker windows are reused by the final pass only when `Diarizer::window_params()` (segmenter id incl. its file-SHA prefix, embedder id, grid, onset, overlap rule, batch size) and the speaker-model ONNX thread count both match; every speaker-model session, live or final, uses `backends::speaker_threads(cores)` (CAM++ output differs across thread counts by up to ~1.5e-5, segmentation does not). Audio given to a live `DiarStream` is quantised exactly as the FLAC writer stores it (`i16_to_f32(f32_to_i16(x))`). Keep `diar_cpu_outputs_are_identical_at_the_same_thread_count` and the bit-exact window assertion in `post_speaker_windows_from_the_meeting_give_the_whole_track_speakers`.
- Live speaker work runs only on the session's one speaker thread (`live::speaker_thread`) at below-normal OS priority with background ONNX sessions (`SessionConfig::background`: per-session ort thread manager whose pool threads lower themselves, spinning off; outputs bit-equal to normal sessions, `diar_background_sessions_equal_normal_sessions_bit_for_bit`); transcription workers never run or wait for it (`post_live_transcription_never_waits_for_speaker_work`). The only OS priority call is `earshot-capture-wasapi::wasapi::lower_current_thread_priority` (through `earshot_runtime::priority`); a thread or pool thread that cannot lower itself stops speaker work with a reason (re-checked after every batch), and other platforms refuse background work. `SPEAKER_MAX_BUFFER` (180 s) is enforced on the send side (`Held::admit`); a stopped track is sent no more audio. Recorded windows are the snapshot of finished batches (`speaker_thread::publish`, which checks the detached flag under the snapshot lock, so a thread left after `LiveConfig::speaker_stop_wait` (2 s) publishes nothing). At the end the session cancels speaker work before finishing the workers. Speaker-thread code never holds the store, a FLAC writer or a `Services` handle. Tests of what speaker work computes set `LiveSpeakers::background = false` (below-normal threads starve on a saturated host); only production (`with_live_speakers`) sets true, exercised by the production-loader test and the priority tests.
- `live-speakers/*` (speaker embeddings, biometric) and `live-stretches/*` (raw transcript) in local_state are transient: only the final pass reads them, and it deletes them in its write transaction on every path and then calls `Store::flush_erasures`; a failed or cancelled final pass keeps them for a retry, and a cancelled cleanup in the CLI deletes the meeting's speaker records (`speakers::forget_speakers`). Any new device-local record holding embeddings or transcript text follows the same rule, and a future meeting deletion must sweep these prefixes. Erase local values only with `Store::delete_local_value` / `StoreTx::delete_local_value` (`device_id` refused); on-disk erasure tests keep a second connection open across the close. A device-local record that cannot be read is a warning and a whole-track fallback, never an error; version and header go outside the payload.
- Speaker detection timing (T6.13d4) is the device-local setting `settings/speaker-timing` (`during` default, `after`, `after-on-battery`), read once per session start as `StoredTiming` (an unknown stored value is reported and the default used). Live speaker models load only through `LiveSpeakers::models` (`SpeakerLoader`), called by `start_live` after the off decision and before the FLAC writers and meeting rows; with speaker work off from the start nothing loads and the track gets the reason-only record `0 (u32 LE) | reason UTF-8` at the same `live-speakers/<meeting>/<track>` key (`StoredSpeakers::Off`, final pass reports `Diarised { reason }`); window records keep version >= 1, `speakers::decode` is the only reader, and one key deletion erases both forms. A third record form needs one tagged envelope first. On battery, `after-on-battery` stops work through `SpeakerThread::stop_work` within `power_poll` (5 s) plus the model call in progress; `stop_work` never overwrites the reason of a thread that already ended (a crash).
- Device-local values are written only through `earshot_runtime::local::set` / `set_tx` with a registry `LocalKey` (`MeetingRecord::key` / `DeviceRecord::key`); `local_state_is_written_only_through_the_registry` scans every workspace member except xtask, earshot-store and `net_guard::TEST_SUPPORT_PACKAGES`, following module declarations from lib.rs/main.rs and leaving out modules declared under `#[cfg(test)]`, and fails on a direct `set_local_value(`. A new meeting-keyed record joins the `meeting_records!` list (and `delete_tests::production_key`), a device-wide one a `DeviceRecord` variant. A record whose format the store must read lives in earshot-store, with the runtime's key pinned to it by a test.
- Meeting deletion goes only through `Services::delete_meeting` -> `Store::delete_meeting`: each audio file before its row, then one transaction (core `delete_meeting` tombstones and clears every row, export records and the `export-lease/<meeting>` row removed, local keys erased), then a TRUNCATE checkpoint (a `Busy` after it means the deletion is committed). People and voiceprints are kept, and only `Store::remove_person` (T9.1u, the Speakers page, through `edit::remove_person`, which refuses the user) deletes them: one transaction clears and tombstones the identity's person rows, forgets its voiceprints and centroids and sends its speaker rows back to the first free "Speaker N", unlinked; written text is not rewritten. `edit::remove_person` also refuses anyone the user was merged into, because a removal takes the whole identity. The final pass matches voiceprints inside its write transaction, so a removal cannot race it. Every runtime job on a meeting (live session, final pass, export) holds a `Services::lease_meeting`; deletion while one is held is retryable `RuntimeError::MeetingBusy` (one process only); cross-process, every store write that must not follow a deletion checks `meta.deleted` (final pass, summary, export `live_meeting` at record read, create claim and final record write).
- Exports of one meeting are serialised by the database lease `export-lease/<meeting>` (owner pid + thread token, export-clock stamp) held from the record read to the final record write, taken in an IMMEDIATE transaction; 30 s wait, then retryable `ConcurrentEdit`; 2 min staleness in either clock direction; nested holds on one thread are counted by a drop guard; the optimistic sibling, claim and stamp checks stay as the second line. Store export tests that count `with_store` calls by position include the lease take (first) and release (last).
- Speaker identities (T6.25): `speaker-identities/<meeting>` (format in `earshot_store::identities`, version outside the payload) holds the final pass's per-speaker centroids (biometric) with the name and person the pass gave each row; rewritten in the final pass's write transaction (tombstoned speakers dropped, "Me" never recorded), erased by meeting deletion, and every path that forgets an identity's voiceprints (`Store::forget_voiceprints`, `Store::remove_person`) drops that identity's entries (`identity_of`: person plus `merged_into` chains) through `forget_identity_biometrics`. A re-run carries a speaker row only through `identities::match_previous`: same track, cosine >= the calibrated voiceprint threshold of the exact model, one to one, edited rows first; only user edits are carried; another embedding model carries nothing (`PostWarning::SpeakerNamesNotCarried`). - Capture modes (T6.27): `WasapiSource::start` takes a `CaptureMode`; `InRoom` opens no loopback (no reference, no canceller, no echo locks, in-person policy); `run_capture` stays the one loop with an optional loopback track; `record_raw` is always two-track. - Bluetooth hands-free detection (T6.24) is only `earshot_capture_wasapi::endpoint::classify_mic`, a pure function over `EndpointProperties` (nothing off a Bluetooth bus is ever Bluetooth); endpoint property reads live only in `wasapi::endpoint_properties` (a missing property is `None`); the warning is judged on the mic opened at start and reaches the UI through `start_live_with_warnings` (after Started and the LiveBackend events, before any audio event). - The AMI SDM condition (`ami_sdm`, T2.5c) goes only through `refs::load_ami(.., AmiMic::Sdm)`: the `asr.wer_ami_ihm` speakers, oracle segments, references and scoring, decoded from `<meeting>.Array1-01.wav`; it is informational (`m2_prod`'s `informational` list on the production default model, an `accept m2` Check, a `model_eval` opt-in corpus), never a Measurement, threshold or `QUALITY_ORDER` input. Every AMI recording `load_ami` reads must be 16 kHz with exactly one channel (never mixed down).
- NPU telemetry check (T8.3b): `cargo xtask qnn-etw` fails closed: it needs complete captured output, a complete trace with events from the probe process (including ONNX Runtime's `ProcessInfo` MEASURES event), every `Data` element parsed, every telemetry-keyword event in `qnn_etw::SYSTEM_EVENTS` with its fields, and no transcript word in any traced value (values are never printed). The NPU conversion is trusted only when its files match `conversion.json` (`backends::verify_qnn_conversion`).
- An export holder re-stamps its `export-lease/<meeting>` row in every later store access (claim, last look before a create's rename, final record write); an access that finds the lease no longer its own stops with retryable `ConcurrentEdit` before writing. The meeting check and the record write it guards run in one IMMEDIATE transaction (`Store::immediate`), meeting check first.
- `asr_eval/refs.rs` has no test module: its tests live in `asr_eval/refs_tests.rs` (asr_eval only); `model_eval`, `diar_eval` and `xtask::t613` include `refs.rs` by path and never compile its tests.
